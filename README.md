# shiftmate-holidays

교대근무 알림 앱 **shiftmate**가 받아가는 **한국 공휴일 데이터**를 두는 곳이다.

앱은 이 저장소의 raw JSON만 읽는다. **공공데이터포털 API를 앱에서 직접 부르지 않는다** —
API 키가 APK 디컴파일로 노출되고, 일 10,000건 한도를 전체 사용자가 공유하므로 사용자가
늘면 즉시 초과하기 때문이다.

```
https://raw.githubusercontent.com/kimash0420/shiftmate-holidays/main/holidays/2026.json
```

## 데이터 형식

```json
{
  "year": 2026,
  "updated": "2026-08-23",
  "source": "holidays==0.103",
  "holidays": [
    { "date": "2026-01-01", "name": "신정연휴" },
    { "date": "2026-03-01", "name": "삼일절" }
  ]
}
```

- **법정공휴일·대체공휴일·임시공휴일·노동절**을 담는다.
- `holidays`는 날짜순으로 정렬돼 있고 날짜가 중복되지 않는다.
- **`updated`는 마지막으로 성공적으로 만든 날짜다.** 공휴일 목록이 그대로여도 갱신된다.
  앱은 이 값으로 "아직 관리되고 있는가"를 판단해 30일 넘게 멈추면 경고 배너를 띄운다.
  만들기에 실패하면 워크플로가 **아무것도 커밋하지 않으므로** 날짜가 자연히 멈춘다.
- **`source`는 어느 라이브러리 판이 만들었는지**다. 값이 이상할 때 판올림을 되짚는 단서다.

## 출처: `holidays` 패키지 (API 키 없음)

처음에는 공공데이터포털 「특일 정보」 API로 짰다가 **2026-08-23에 갈아탔다.**

| | 특일 정보 API | **`holidays` 패키지** |
|:---|:---|:---|
| 키 | 필요. **활용기간 24개월** | **불필요 — 만료가 없다** |
| 노동절 | **없다**(관공서 공휴일 기준) | 있다 |
| 임시공휴일 | 1차 출처 | 릴리스로 들어온다(2023-10-02·2025-01-27 등 확인) |
| 장애 | API 다운·한도에 걸린다 | 네트워크를 안 쓴다 |

갈아탄 이유는 둘이다. **① 24개월 뒤 키가 만료되면 파이프라인이 죽는데 그 시점은 앱이
배포된 지 한참 뒤다.** ② 이 앱 사용자는 **노동절에 주간 근무를 쉬는데**, 특일 정보는
관공서 공휴일 기준이라 노동절이 아예 응답에 없다.

대신 **임시공휴일 반영이 PyPI 릴리스 시차에 종속된다.** 그래서 워크플로가 매 실행마다
`holidays`를 최신으로 올리고(`pip install -U`), 생성기에 **축소 감지**를 뒀다 — 전에 있던
공휴일이 사라지면 실패시켜 사람이 보게 한다. 출처가 하나뿐일 때 가장 위험한 것은
그 출처가 **조용히 나빠지는 것**이다.

> **참고 — 검토했다가 탈락시킨 것**: [Nager.Date](https://date.nager.at)는 키가 필요 없지만
> 2026·2027년에 **11건이 빠졌다**(2026-03-01 삼일절·2026-08-15 광복절·2026-10-03 개천절 등).
> 주말에 걸린 본 공휴일을 빼고 대체휴일만 준다.

## 자동 갱신

`.github/workflows/update-holidays.yml`이 **매주 월요일 05:20 KST**에 올해·내년치를 다시
만들어 커밋한다. 임시공휴일이 지정되면 저장소 **Actions 탭 → update-holidays → Run workflow**로
즉시 돌린다. **시크릿 설정이 없다** — 저장소를 클론해 바로 돌릴 수 있다.

> 주 1회인 이유: 가장 큰 리스크가 "임시공휴일이 지정됐는데 갱신이 늦어 전체 사용자의
> 알림이 틀리는 것"이라 반영 지연을 최대 30일에서 7일로 줄였다. 공개 저장소라 Actions
> 사용량 비용이 0이다.

## 직접 실행

```bash
pip install -r requirements.txt
python scripts/build_holidays.py            # 올해 + 내년
python scripts/build_holidays.py 2027       # 연도 지정
```

공휴일이 줄어들어 멈췄고 **그것이 옳은 수정임을 확인했다면**:

```bash
python scripts/build_holidays.py --allow-shrink
```

테스트(네트워크 없이 돈다):

```bash
pip install -r requirements-dev.txt
python -m pytest tests -q
```

## 임시공휴일을 손으로 넣어야 할 때

라이브러리 릴리스가 늦으면 `holidays/<연도>.json`을 직접 고쳐 커밋해도 된다. 날짜순 정렬과
`updated` 갱신만 지키면 앱은 구분하지 않는다. **다음 자동 실행이 그 날짜를 지우려 하면
축소 감지가 막아준다** — 그때 라이브러리가 따라잡았는지 확인하고 판단하면 된다.
앱의 «수동 휴일 지정»으로도 대응할 수 있다.

## 이 저장소의 출처

개발 원본은 `AUTOPILOT/shiftmate-holidays/`이고 여기로 `git subtree split`해 게시한다.
**이 저장소에서 직접 고치면 다음 게시에 덮인다** — 워크플로가 만드는 `holidays/` 커밋은 예외다.
